# Code Review Skill

## 描述

自动代码审查技能，用于分析 Pull Request / Merge Request 或本地 diff，
识别潜在问题并生成结构化报告。

## 使用场景

- 审查 Gitee/GitHub/Codeup 的 PR/MR
- 审查本地分支的变更
- 自动化 CI/CD 流程中的代码质量检查

## 审查规则

### 必须检查项

1. **安全性**
   - SQL 注入风险
   - XSS 漏洞
   - 敏感信息泄露（密钥、密码、token）
   - 路径遍历攻击

2. **性能**
   - N+1 查询问题
   - 未索引的数据库查询
   - 内存泄漏风险
   - 循环依赖

3. **可维护性**
   - 函数过长（>50 行）
   - 复杂度过高（圈复杂度 >10）
   - 重复代码
   - 缺少文档字符串

4. **最佳实践**
   - 错误处理是否完整
   - 日志记录是否充分
   - 测试覆盖率是否足够
   - 命名是否符合规范

### 审查流程

1. 读取项目规则和仓库特定规则
2. 获取 PR/MR 上下文（标题、描述、提交历史、文件列表）
3. 分析每个变更文件的 diff
4. 记录结构化 finding（包含文件、行号、严重级别、描述）
5. 生成中文审查报告

### Finding 格式

```json
{
  "file": "path/to/file.py",
  "line": 42,
  "severity": "high",
  "title": "SQL 注入风险",
  "description": "用户输入直接拼接到 SQL 语句中，建议使用参数化查询"
}
```

### 严重级别定义

- **critical**: 安全漏洞、数据丢失风险
- **high**: 严重 bug、性能瓶颈
- **medium**: 代码质量问题、可维护性问题
- **low**: 风格问题、建议优化

## 输出模板

```markdown
# 代码审查报告

## 结论

[通过/需要修改/阻塞合并]

## 阻塞问题 (Critical)

- [ ] ...

## 高风险问题 (High)

- [ ] ...

## 一般建议 (Medium/Low)

- [ ] ...

## 测试建议

- [ ] ...
```
